This plan covers the full backend + frontend restructure. Work is sequenced so the schema/enum changes land first (everything else depends on them), then backend logic, then the frontend foundation (theme/routing/auth types), then UI. Each section ends with a verification step.

> **Scope note:** This is a large change. I will implement it section-by-section, compiling/building after each major area, and report progress. Mock data removal, the landing redesign, and dashboard rewrites are the largest frontend pieces.

### A2. Granular Admin permissions (new Permission model)

**Schema additions:**

```prisma
enum Permission {
  ALL
  INTAKE          // create/acknowledge/triage intake
  SCHEDULE        // assign/route to departments
  COMPLAINTS      // view/manage all complaints
  REPORTS         // audit/reports
  USERS           // manage users
  DEPARTMENTS     // manage departments
  ROUTING         // routing rules
  SLA             // sla config + monitoring
  AUDIT           // audit events/logs
  APPROVALS       // approvals inbox participation
}

model UserPermission {
  id        String     @id @default(uuid()) @db.Uuid
  userId    String     @map("user_id") @db.Uuid
  user      User       @relation(fields: [userId], references: [id], onDelete: Cascade, onUpdate: Cascade)
  permission Permission
  grantedAt DateTime   @default(now()) @map("granted_at")
  @@unique([userId, permission])
  @@index([userId])
  @@map("user_permissions")
}

// on User:
isSuperAdmin Boolean @default(false) @map("is_super_admin")
permissions  UserPermission[]
```

**New files:**

- `backend/src/common/decorators/permissions.decorator.ts` — `@Permissions(...)` + metadata key.
- `backend/src/common/guards/permissions.guard.ts` — `PermissionsGuard`. Passes if: caller `isSuperAdmin === true`, **or** caller has `ALL`, **or** caller has one of the required permissions. Only meaningful for `ADMIN` role users; non-admins are denied by `RolesGuard` upstream.
- Register `PermissionsGuard` globally (after `RolesGuard`) in `app.module.ts`.

**`auth.service.ts` / `jwt.strategy.ts`** — extend `AuthenticatedUser` and JWT payload to include `permissions: Permission[]` (and `isSuperAdmin`). `validate()` loads the user's permissions from DB each request.

**`users.service.ts` / `users.controller.ts`** — `create`/`update` accept `permissions: Permission[]`. On create, replace the user's `UserPermission` rows in a transaction. `findMany`/`findPublicById` include `permissions`. The Super-Admin-only endpoints (departments, routing-rules, sla config, users) gain `@Permissions(DEPARTMENTS|ROUTING|SLA|USERS)` _in addition to_ the existing role gate — but since Super Admin is now an `ADMIN` with `isSuperAdmin`, the role gate becomes `@Roles(ADMIN)` + a check for `isSuperAdmin` OR the relevant permission.
